# oa-problems

The shared question bank for [OA Judge](../oa-judge). One directory per problem. Everyone who
uses the judge clones this into `oa-judge/problems/`; when anyone adds a problem here and it
passes CI, everyone gets it on their next **Sync**.

## Layout

```
<problem-id>/
├── problem.json      metadata: title, company, difficulty, tags, languages, limits, links, author
├── statement.md      the problem statement (Markdown)
├── editorial.md      approach / solution notes (optional)
├── reference.cpp     verified correct solution — the source of truth for expected output
├── stub.cpp          starter code shown in the editor
├── generator.py      random-input generator: argv[1]=seed, argv[2]=integer size hint (optional)
└── tests/
    ├── sample/       01.in / 01.out … shown to the solver
    ├── edge/         curated bounds / degenerate / adversarial cases (durable)
    └── hidden/       generated by the tooling: edge cases + random, expected output from reference
```

`reference.*` is authoritative: hidden `.out` files are produced by **running the reference**,
never hand-written. See [FORMAT.md](FORMAT.md) for the full contract.

## Adding a problem

Easiest: use the judge's **Add Problem** form (writes a valid package, runs the verifier, and
publishes a branch). By hand:

1. Create `<problem-id>/` with the files above.
2. From the `oa-judge` checkout, generate hidden tests: `python3 make_hidden.py <problem-id>`.
3. Verify: `OAJ_PROBLEMS_DIR=$PWD python3 /path/to/oa-judge/verify_all.py`.
4. Open a PR. CI re-runs the verifier; a problem whose reference doesn't reproduce its own
   samples cannot merge.

## Verifying locally

```
OAJ_PROBLEMS_DIR="$PWD" python3 /path/to/oa-judge/verify_all.py
```
